# ARMADILHAS.md — o que já quebrou produção

Arquivo de contexto técnico. Cole junto com MERCADO.md quando a conversa for de código.
Cada item aqui já aconteceu de verdade em um dos três apps e custou tempo ou dinheiro.


**`Alert.alert` é no-op no React Native Web.** *Sintoma:* diálogos de erro, permissão negada e menus de ação não aparecem na web/PWA — sem erro no console, sem sinal nenhum. *Causa:* em `react-native-web` a implementação inteira é `class Alert { static alert() {} }`, função vazia, sem fallback para `window.alert`. *Prevenção:* em projeto Expo que exporte para web, tratar como inutilizável desde o dia um e construir modal próprio (`AlertModal` + hook `useAppAlert`, suportando a forma com array de botões); grep por `Alert.alert` no início, não depois do relato.

**Lookbehind em regex quebra o Safari do iOS 15 e abre o app em BRANCO.** *Sintoma:* tela branca no iPhone, sem erro visível, sem tela de falha. *Causa:* `(?<=` e `(?<!` só existem no Safari a partir da 16.4; antes disso é SyntaxError de PARSE, que mata o bundle inteiro, não só a função. Em 20/08/2026 o app ia para a Play Store com três arquivos assim, e nenhum teste pegou porque testes rodam em Node. *Prevenção:* cortar frase com `match(/[^.!?]+(?:[.!?]+|$)/g)` e portão que varre o projeto atrás da sequência proibida. **Regra geral: recurso de JS moderno se checa contra o Safari, nunca contra Node ou Chrome — os dois mentem sobre o que o iPhone aguenta.**

**Google Tradutor reescreve o DOM e quebra o React.** *Sintoma:* bugs bizarros sem erro nenhum — typewriter cortado no meio, palavras trocadas ("Celeste" virando "celeste"), inputs e chips que nunca aparecem. O E2E automatizado passa sempre. *Causa:* o auto-translate envolve os nós de texto em `<font>` e reescreve o conteúdo; o React perde a referência dos próprios nós. Dispara sozinho em app bilíngue. Em 09/08/2026, TODOS os "bugs" vistos em produção eram isso. *Prevenção:* blindar em duas camadas antes do primeiro deploy — no HTML estático (`<html translate="no" class="notranslate">` + `<meta name="google" content="notranslate">`, aplicado no `dist/index.html` dentro do script) e em runtime no App.js para web.

**`.bat` gravado em LF falha em silêncio.** *Sintoma:* a tarefa agendada reporta sucesso (`LastTaskResult = 0`) e o script não rodou; erros do tipo `'level' não é reconhecido` (de `errorlevel` partido). *Causa:* o cmd exige CRLF; com LF ele parte as linhas e o `.bat` termina sem erro fatal. BOM também quebra a primeira linha. *Prevenção:* gravar com `WriteAllText` juntando por `\r\n` em UTF-8 sem BOM, e conferir que `(?<!\r)\n` dá zero. **Regra maior: tarefa que reporta sucesso não prova que rodou — verificar pelo EFEITO (data do arquivo gerado), nunca pelo código de saída.**

**`open(p,'w')` direto trunca o arquivo se a escrita falhar.** *Sintoma:* arquivo de 155 KB vira 0 bytes (aconteceu em 22/08/2026, num erro de encoding de surrogate). *Causa:* o modo `'w'` trunca ANTES de escrever; falhando no meio, o original já se perdeu. *Prevenção:* escrever em `p + '.tmp'` e só então `os.replace(tmp, p)`; com emoji, ler e escrever com `errors='surrogatepass'`; antes de mexer em arquivo sem git, copiar para `.bakN`.

**Sonda de scroll com `scrollTop` mente.** *Sintoma:* o usuário relata "não consigo rolar" e a sonda responde "rola normal", com todos os portões de deploy verdes — custou três relatos seguidos e dois diagnósticos errados. *Causa:* `element.scrollTop = N` funciona mesmo quando a área não é rolável ao toque: o script rola, o dedo não. *Prevenção:* medir com toque real (`Input.dispatchTouchEvent` via CDP, touchStart + vários touchMove + touchEnd, em viewport de celular com emulação de toque). A causa é quase sempre a mesma família: `cardStyle` do Stack sem `flex: 1`, ou tabBar customizada fora do fluxo (`return null` e `position:absolute` dão o mesmo defeito; nas rotas sem dock, devolver `<View style={{height:0}} />`).

**Deploy fora do script derruba a produção.** *Sintoma:* o site passa a servir o template cru com placeholders literais e o bundle vira 404 (03/08/2026). *Causa:* o deploy genérico na raiz sobe o diretório do projeto em vez do build — a raiz não declara `outputDirectory`, a plataforma adivinha errado e não reclama. *Prevenção:* publicar só pelo script do projeto, que monta a saída, escreve a config com rewrites, roda a regressão E2E como portão e só então publica. Ao conferir, lembrar que as telas são chunks lazy — procurar a string no bundle principal dá zero mesmo com deploy correto.

**Sincronizar de uma cópia errada apaga rota em produção.** *Sintoma:* rota some e ninguém percebe até um usuário reclamar (a busca de cidades caiu em 01/08/2026 — quem mora fora das capitais não achava a cidade). *Causa:* sincronizar backend a partir de cópia obsoleta; `tar -x` sobrescreve mas não apaga, então módulos órfãos ficam no disco enquanto o arquivo principal volta a uma versão antiga sem as rotas — e sem git no servidor, sem rollback. *Prevenção:* uma única fonte da verdade declarada por projeto e deploy por script que faz backup de código e banco antes de copiar. **Alerta:** contagem de testes divergindo entre local e servidor significa repos divergidos — parar e comparar a lista de arquivos dos dois lados antes de publicar.

**Playwright vaza perfil de teste a cada launch.** *Sintoma:* disco enche em dias — 309 pastas órfãs, 18,9 GB em 5 dias, 90% do Temp (medido em 25/08/2026). *Causa:* o Playwright cria a pasta de perfil e não apaga; uma suíte de 92 testes com 3 portões gera dezenas de perfis por deploy. *Prevenção:* `try/finally` com `browser.close()`, ou `userDataDir` fixo reusado. Para identificar pasta órfã com segurança, procurar `package.json`/`app.json`/`.git` dentro dela — filtrar por extensão `.js` dá falso positivo, porque as extensões embutidas do Chrome levam milhares de arquivos.

**Portão que só fala HTTP passa 14/14 com o app quebrado.** *Sintoma:* o app ficou inutilizável para 100% dos usuários novos ("No safe area value available") enquanto o portão de verificação passava em todos os checks. *Causa:* o portão testava bundle carregando, locales servindo e APIs respondendo — nada disso prova que uma TELA MONTA. *Prevenção:* portão E2E com navegador real, e **provar o portão de propósito**: reintroduzir o bug exato, confirmar que ele falha, restaurar. É isso que separa um portão que funciona de um que parece funcionar. Dois corolários: portões múltiplos precisam AGREGAR veredito, nunca encadear com `&&` (o primeiro grep sem match silencia todos os seguintes); e há classes de bug que nenhum portão pega, porque o E2E não abre a tela onde eles moram.

**Gate de paywall condicionado à variável errada libera o produto inteiro.** *Sintoma:* "consegui usar várias coisas várias vezes e não pediu pra assinar" — nove telas pagas liberadas, repetição infinita. *Causa:* o bloqueio estava condicionado a uma flag de acesso que outro contexto fixava como `true` para sempre num modo de uso legítimo. *Prevenção:* derivar uma variável explícita de acesso pleno e usá-la em TODO gate (bloqueio, render guard, trava de uso único); nunca a flag crua. Se aparecer "não pediu pra assinar" numa tela nova, checar primeiro se ela usa a flag crua — é o padrão-fonte desse bug. Irmão do mesmo dia: **preço sempre fixado no servidor**, porque o cliente gravava valor mentiroso.
